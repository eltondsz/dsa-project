# Technical Contracts & Specifications

To ensure the Kotlin Android Shell and the Python Brain communicate flawlessly, you must enforce the following data structures and API signatures.

## 1. Chaquopy Bridge API Contract

These are the core Python functions that the Kotlin frontend will invoke via Chaquopy. Kotlin will load the Python module and use `.callAttr()` to pass data back and forth.

- `init_database() -> bool`: Initializes the SQLite connection and builds required tables.
    - **Crucial Android/Chaquopy Constraint:** In a standard Python environment, calling `sqlite3.connect('database.db')` works perfectly, but in an Android environment, it will crash with an "unable to open database file" error. The Python engine must construct an absolute file path using `os.path.abspath(os.path.dirname(__file__))` to successfully write to the Android storage.
- `process_incoming_ble(raw_payload: bytes) -> dict`: Receives a raw byte-string from Kotlin, decrypts it using the Noise Protocol Framework, updates the local database, and returns a JSON-serializable dictionary for the UI to render.
- `prepare_outgoing_message(recipient_uuid: str, message: str) -> bytes`: Takes plaintext from the Kotlin UI, encrypts it, attaches the mesh routing headers, and returns the raw bytes for Kotlin to broadcast.
- `trigger_panic_wipe() -> bool`: Instantly drops all SQLite tables and clears active encryption keys.

## 2. SQLite Database Schema (Python Engine)

The Python backend will manage local storage for the offline store-and-forward mesh routing.

- **`peers` Table:**
    - `peer_id` (TEXT, Primary Key - UUID)
    - `display_name` (TEXT)
    - `public_key` (BLOB)
    - `last_seen` (INTEGER - Unix Timestamp)
- **`messages` Table:**
    - `msg_id` (TEXT, Primary Key)
    - `sender_id` (TEXT, Foreign Key)
    - `recipient_id` (TEXT, Foreign Key)
    - `payload` (TEXT - Stored encrypted, decrypted dynamically for the UI)
    - `timestamp` (INTEGER)
    - `status` (INTEGER - 0: Draft, 1: Cached/Pending, 2: Delivered)

## 3. BLE Packet Structure (Byte Map)

To respect Android Bluetooth Low Energy MTU limits and support multi-hop mesh routing, Python must output raw bytes in this exact format before passing them to Kotlin.

- **Header (18 Bytes):**
    - `Byte 0`: Hop Count (Integer 1-7).
    - `Byte 1`: Packet Type (e.g., 0x01 for Direct Chat, 0x02 for Group, 0x03 for Handshake).
    - `Bytes 2-17`: Message UUID (16 bytes).
- **Payload (Variable):**
    - `Bytes 18+`: The ciphertext payload generated by the Noise protocol cipher state (e.g., utilizing the `Noise_XX` pattern for mutual authentication).

## 4. Build System & Dependency Management

### 4.1 Python Native Environment (Core Logic)

- **Directory:** `/python_core/`
- **Dependency Manager:** Poetry (`pyproject.toml`).
- **Testing Engine:** `pytest`.
- **Workflow:** The Python logic must be unit-tested locally via `pytest` independently of Android. All core functions (`process_incoming_ble`, `prepare_outgoing_message`, SQLite operations) must pass local unit tests.
- **Android Handoff Rule:** Prior to an Android build, dependencies must be exported from Poetry to a standard format: `poetry export -f requirements.txt --output requirements.txt`. Chaquopy will read this exported file to bundle the APK.

### 4.2 Android Native Environment (Kotlin Shell)

- **Directory:** `/android_app/`
- **Build System:** Gradle with Kotlin DSL (`build.gradle.kts`). Do not use Groovy.
- **UI Framework:** 100% Jetpack Compose. Do not generate or modify legacy XML layouts.
- **Architecture Pattern:** MVVM (Model-View-ViewModel) to manage Compose UI state and background Bluetooth lifecycle.
- **Hardware APIs:** Use modern `android.bluetooth.le` classes for scanning, advertising, and MTU negotiation.

```text
    ├── pyproject.toml           # Poetry configuration

```

## 6. Mandatory Android Permissions

To prevent the app from crashing upon launch, the Kotlin codebase must explicitly request the following permissions in the `AndroidManifest.xml` and handle runtime permission requests in Jetpack Compose:

- `BLUETOOTH_SCAN`, `BLUETOOTH_ADVERTISE`, `BLUETOOTH_CONNECT` (Required for Android 12+)
- `ACCESS_FINE_LOCATION` (Required for BLE scanning on Android 11 and lower)
